# spire

终端里的爬塔:类杀戮尖塔的单人构筑 roguelike,纯键盘、vim 风格操作。
Rust + ratatui,和 `neon/` 同一套技术栈(ratatui 0.30 + crossterm 0.29 + 24 位真彩)。

## 这是什么

一局 = 爬一张 15 层 + Boss 层的地图。每层一种房间:战斗、精英、事件、商店、营火、宝箱。
用一副牌打怪:每回合 3 点能量,抽 5 张牌,打出手牌消耗能量,回合结束弃掉手牌,
敌人按自己的意图行动。打赢给金币与选牌奖励(三选一不会重复),精英和 Boss 额外给遗物,
营火能回血或升级牌,商店能买牌/遗物/药水,还能花钱删牌。

费用和能量一律写成 `(3)/(3) energy`、`(1) energy` 这种带括号的样子:括号按
"谁的颜色"上色(玩家能量用角色色,卡牌费用用卡牌所属颜色:红绿蓝紫白,
其余一律灰),括号里的数字保持默认色。卡牌列表里写成 `(1) Strike`;
只有战斗手牌那一行为了省地方不写括号,直接 `1 Strike`,数字照样按颜色,整行居中。
牌面说明里"获得能量"也写成 `(N)`(拿到几点就写几),不再用 `[E]` 这种符号。

玩法要点都在原作那一套里:能量、格挡、力量/敏捷、易伤/虚弱/脆弱、
抽牌堆-弃牌堆-消耗堆的循环、牌组里会混进伤口/粘液这类状态牌与诅咒。

界面只有两行固定行:顶栏是玩家状态(生命、能量、金币、层数、牌数、遗物数),
底栏是当前界面的按键提示与消息。中间全是内容。

## 技术栈

- Rust 2021(rustc 1.98)
- ratatui 0.30.2 / crossterm 0.29 / unicode-width 0.2.2
- 颜色走 24 位真彩(`38;2;r;g;b`),需要 `COLORTERM=truecolor`
- 随机数自己实现(xoshiro256** + splitmix64):不引第三方库,同一个 seed 必定复现同一局

## 构建与运行

```bash
cd slay-the-spire
cargo build --release
./target/release/spire              # 随机种子
./target/release/spire --seed 7     # 固定种子,方便复现
```

命令行:

```
spire [options]
  --seed <n>      固定种子
  --dump <what>   打印数据后退出(cards|enemies|relics|potions|events)
  -h, --help      帮助
  -V, --version   版本
```

## 键位

全部动作用键盘完成,不需要鼠标。

开始界面(启动就进这里):

| 键 | 作用 |
| --- | --- |
| `j` `k` | 选 continue / new game / compendium / quit |
| `enter` | 确认 |
| `q` | 退出 |

new game 之后先选角色(现在只有铁甲战士能开局,别的角色会写明缺什么),
选完直接进开局的第一个事件:Neow 的祝福,四选一之后正式上地图。

compendium 里三本册子:`card library`(全部卡牌)、`relic collection`(全部遗物)、
`potion lab`(全部药水)。每本上面一行标签页,下面是"列表 + 详情":

| 键 | 作用 |
| --- | --- |
| `h` `l` / `tab` | 换标签页(循环) |
| `j` `k` | 在页内选条目(循环) |
| `g` `G` | 首 / 尾条目 |
| `1` `2` `3` | cards / relics / potions |
| `esc` | 返回 |

标签页按参考实现的组织方式分:卡牌是 `Red Green Blue Purple Colorless Status Curses`
(状态牌和诅咒各自成页,不混进无色),遗物按阶,药水按稀有度。
选中的标签字是黄的、底色是本色(白/灰底这种亮底用深黄,不然看不清);
没选中的字灰、底色是自己的颜色掺灰。

列表每行:左边费用 `(1)` + 名字,右边是目标标签(`[enemy]` / `[self]` / `[all enemy]`),
中间只有没实现时才写 `(not implemented)`。右侧详情直接用升级界面的版式:
费用在左、名字/类型/正文居中,上半本体、下半升过级的,中间一条接边框的分隔线。

地图界面:

| 键 | 作用 |
| --- | --- |
| `h` `j` `k` `l` | 在可达的节点之间切换 |
| `enter` / `space` | 进入选中的节点 |
| `g` / `G` | 第一个 / 最后一个可达节点 |
| `d` | 看牌组 |
| `r` | 看遗物 |
| `p` | 在顶栏挑药水(`h`/`l` 换瓶,`enter` 喝) |
| `?` | 帮助 |
| `:` | 命令行 |

战斗界面:

| 键 | 作用 |
| --- | --- |
| `1`-`9` `0` | 选中并打出第 n 张手牌(`0` 是第 10 张) |
| `h` `l` | 左右移动手牌光标(循环) |
| `j` `k` | 上下移动敌人光标(循环,自动跳过已死目标) |
| `enter` | 打出选中的牌 |
| `e` / `space` | 结束回合 |
| `d` / `D` / `X` | 看抽牌堆 / 弃牌堆 / 消耗堆 |
| `p` | 顶栏挑药水(`h`/`l` 换瓶,`enter` 喝,`1`-`3` 直接喝,`t` 再 `1`-`3` 丢;需指定敌人的会让你先选目标) |

各种列表与选择界面:

| 键 | 作用 |
| --- | --- |
| `j` `k` | 上下移动;奖励界面:在金币/卡牌/遗物/药水之间跳 |
| `h` `l` | 奖励界面:在三张候选牌之间循环 |
| `g` / `G` | 到顶 / 到底 |
| `enter` | 确认(拿奖励、买、升级、删除、进入事件选项) |
| `c` | 奖励界面:跳过三选一 |
| `esc` / `q` | 取消 / 离开 |

命令行(`:` 进入):

```
:q :quit            退出
:help               帮助
:deck :relics :potions :discard :exhaust     打开对应列表
:seed               显示本局种子
:quaff N :toss N    喝掉 / 丢掉第 N 瓶药水
:new [seed]         开新的一局
```

一局结束后:`r` 用同一种子重开,`n` 换新种子重开,`q` 退出。

## 内容规模

全量语料来自 `refs/slay-the-cli/data/corpus/*.json`,由 `tools/gen_corpus.py`
生成 `src/core/corpus.rs`(只读展示数据:名字、类型、稀有度、费用、描述文本)。
标记语言(`[base|up]`、`{{C|Id|Display}}`、`$Keyword`、`@GE`、`<br>`)按参考实现的
`src/cli/text/markup.ts` 解析;`tools/check_corpus.py` 会调参考实现自己的解析器
逐字段对账(名字/正文/升级正文/颜色/类型/稀有度/池/目标/费用),目前 593 条全一致。
图鉴列的就是这份语料;能不能真的打出来/用出去由手写的数据表决定,
两边靠 `core/content_tests` 里的契约测试钉住(已实现的 id 必须能在语料里找到)。

| 语料 | 条数 | 已实现 |
| --- | --- | --- |
| 卡牌 | 370 | 57 |
| 遗物 | 181 | 17 |
| 药水 | 42 | 12 |
| 事件 | 51 | 8(另加开局的 Neow) |
| 角色 | 4 | 1(铁甲战士) |

用 `spire --dump <what>` 可以查已实现的那部分表。

| 内容 | 数量 | 说明 |
| --- | --- | --- |
| 卡牌 | 57 张 | 3 张基础、15 普通、21 罕见、11 稀有,另有 4 张状态牌与 3 张诅咒 |
| 敌人 | 18 种 | 12 普通、3 精英、3 Boss(第一章) |
| 遭遇 | 18 组 | 4 组弱遭遇(前 3 层专用)+ 8 组普通 + 3 组精英 + 3 组 Boss |
| 遗物 | 17 个 | 战斗开始效果、战斗后回血、荆棘、商店折扣、每层金币等 |
| 药水 | 12 瓶 | 3 个格子,伤害/格挡/能量/抽牌/增减益/回血,部分能在地图上喝 |
| 事件 | 8 个 | 每个 2-3 个选项,有的要钱、有的要血、有的塞诅咒 |

卡牌效果是数据驱动的:`cards.rs` 里每张牌写一串 `Effect`,战斗引擎按顺序结算,
所以"消耗手牌再按消耗数量算伤害"这类牌只靠效果顺序就能表达。
升级不是算增益,而是显式写一份升级后的覆盖项(费用/文本/效果),
`--dump cards` 打出来的就是玩家看到的那份文本。

## 架构

```
src/
├── main.rs          命令行解析、终端进出、事件循环、--dump
├── app.rs           输入状态机:所有键位、命令行、光标维护
├── rng.rs           确定性随机(xoshiro256**)
├── core/            纯逻辑,不依赖 ratatui,可以脱离终端单测
│   ├── card.rs      卡牌类型、效果枚举、卡牌实例(升级/本场加成)
│   ├── cards.rs     卡池数据
│   ├── status.rs    增减益与能力(玩家/敌人共用)
│   ├── enemy.rs     敌人类型、招式、意图、AI
│   ├── enemies.rs   敌人与遭遇数据
│   ├── combat.rs    战斗引擎:回合流转、抽牌弃牌、效果结算、敌人行动
│   ├── map.rs       地图生成(6 条路径 + 房间规则)
│   ├── relics.rs    遗物数据
│   ├── potions.rs   药水数据
│   ├── events.rs    事件数据(含开局的 Neow)
│   ├── corpus.rs    全量语料(生成的,图鉴和角色选择读它)
│   ├── roster.rs    角色:起始牌组/血量/遗物,以及能不能开局
│   ├── compendium.rs 图鉴:语料 -> 分组列表
│   ├── save.rs      存档路径与读写
│   └── run.rs       一局流程:推进/奖励/商店/营火/事件/选牌/胜负 + 存档序列化
└── ui/              渲染
    ├── mod.rs       入口、ASCII 画框与文本工具、顶栏与底栏
    ├── theme.rs     配色(延续 neon 的 24 位真彩)
    ├── mapview.rs   地图(每层两行:节点行 + 连接行)
    ├── battle.rs    战斗(角色框 + 敌人纯文本 + 手牌速记 + 详情)
    ├── menu.rs      奖励/商店/营火/事件/宝箱/选牌/结算
    ├── start.rs     开始界面/角色选择/图鉴子菜单
    ├── library.rs   图鉴(列表 + 详情)
    └── overlay.rs   牌组/弃牌/消耗/遗物/药水/帮助 叠加层
```

界面每帧都是整屏重画进 ratatui 的 Buffer,由它做脏区 diff,
所以静止不动时不会往终端写任何字节。

## 测试

```bash
cargo test                      # 逻辑单测:地图生成、战斗结算、流程、键位、内容自检
python3 tools/smoke.py ./target/debug/spire 7 42
python3 tools/check_corpus.py   # 生成的语料 vs 参考实现自己的解析器,逐字段对账
```

`tools/smoke.py` 用 tmux 开一个真终端跑真二进制,按底栏显示的界面名发按键,
一路把地图、战斗、奖励、事件、营火、商店、宝箱、选牌都走一遍,
要求这一局最终落到胜利或死亡(重点是流程不能卡住、界面不能认不出来)。

## 已知边界

- 只有第一章:15 层 + 一个 Boss,打完 Boss 就结算,没有第二、三章与进阶难度。
- 存档只有一个:每次走到地图(每层开头)覆盖写 `$XDG_DATA_HOME/spire/run.save`
  (没有 XDG 就 `~/.local/share/spire/run.save`),开始界面的 continue 读它;
  战斗中途不存,所以退出再进会回到这一层刚开始。结算时清掉。
- 角色只有铁甲战士能开局:另外三个的起始牌还没实现(角色选择界面会写明缺哪些),
  Defect 的充能球、Watcher 的架势也还没做。
- 遗物只有 17 个能用,药水 12 瓶,事件 8 个:语料里全量都在图鉴里,但效果要一个个实现。
- 敌人的召唤/分裂(史莱姆 Boss 分裂、哨卫加农炮)没有做,换成更直接的招式循环。
- 药水只有 3 格且没有丢弃以外的处理方式。
