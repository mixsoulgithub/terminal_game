# neon

一个 less 式的终端分页器,配色会流动:底栏是一根流动的霓虹灯管,正文每个字形按视口位置铺满整圈色相(默认开启),另有一条高斯光带横扫而过。

界面只有正文加一行底栏,没有顶栏:名字、过滤条件、提示消息、行数、进度、开关状态全部压在这一行里。

## 为什么这么做

`Docs/Color.md` 里记录过实测结论:整屏彩色背景 + 彩色文字跑一会儿就卡。那份笔记问的是"终端显示的理论上限在哪"。

neon 用两个手段把这个问题压下去:

1. **脏区 diff**:每帧只重建 Buffer,由 ratatui 对比上一帧,只有变化的格子才会变成终端字节。所以静止时每秒输出 **0 字节**。
2. **颜色量化**:色相量化到 1/128 圈、光带强度量化到 1/16 档。一个格子的颜色只有跨过量化台阶时才变,于是绝大多数格子帧间完全相同,连 diff 都不产生。

单独第 1 条不够:全屏流动意味着每个格子每帧都在变。第 2 条把"每帧都在变"变成"每几帧才变一次",实测降到原来的 1/3。

## 技术栈

- Rust 2021(rustc 1.98)
- ratatui 0.30.2 / crossterm 0.29 / unicode-width 0.2.2
- 颜色走 24 位真彩(`38;2;r;g;b` / `48;2;r;g;b`),不经终端调色板。需要 `COLORTERM=truecolor`

## 构建与测试

```bash
cd neon
cargo build --release
cargo test
./target/release/neon README.md
```

## 用法

```bash
neon [options] [file]
cmd | neon [options]
```

| 选项 | 含义 |
| --- | --- |
| `-n`, `--numbers` | 显示行号(折行产生的续行不重复编号) |
| `-S`, `--no-wrap` | 不折行 |
| `--word-wrap` | 在词边界折行,而不是按显示宽度硬切 |
| `-f`, `--follow` | 跟随文件增长(像 `tail -f`),从文件末尾开始 |
| `--no-anim` | 关闭流动,只留静态霓虹 |
| `--no-rainbow` | 关掉字形上色,只留那条流动的光带(省一半以上字节) |
| `--fps <n>` | 动画帧率,默认 30 |
| `--flow <x>` | 流速倍数,默认 2.0(按 `1.0` 为基准,即默认值的一半) |

## 键位

| 键 | 作用 | 键 | 作用 |
| --- | --- | --- | --- |
| `j` / `k`,方向键 | 上下滚一行 | `space` / `b` | 上下翻一页 |
| `d` / `u` | 半页 | `g` / `G` | 到顶 / 到底 |
| `/` / `?` | 向下 / 向上搜索 | `n` / `N` | 下一个 / 上一个匹配 |
| `&` | 只留命中该串的行(空串清除过滤) | `F` | 跟随文件增长 |
| `m` | 折行开关 | `w` | 按词折行开关 |
| `l` | 行号开关 | `a` | 流动开关 |
| `r` | 全字形上色开关 | `h` | 帮助叠层 |
| `+` / `-` | 加快 / 减慢流速 | `q` | 退出 |
| `esc` | 先清除搜索痕迹,没有搜索时才退出 | 滚轮 | 滚动 |

底栏右侧是六个开关的指示(`-` 表示关闭),左边是名字与当前过滤/提示:

```
 /path/to/file.txt  [filter]  12 of 340 lines match x       340 lines   42%  M-LRAF
 |                   |        |                             |          |    |
 名字                过滤条件  提示消息(搜索/过滤结果)         总行数     进度  开关
```

搜索与过滤都是 smart case:查询里没有大写字母时忽略大小写,有大写就区分。搜索的匹配高亮分两色,当前匹配更亮。

## 跟随、过滤、折行

- **跟随**(`F` 或 `-f`):每 200ms 查一次文件大小,只读取新增的那一段字节拼到文档末尾。原来贴着底部就继续贴底(像 `tail -f`),你往上翻过之后就不再被拽回去。文件被截断或轮转时整份重读。
  - 读到一半的多字节字符会留在缓冲区等下一次,不会被劈成乱码。
  - 文件最后一行还没等到换行符时也照样显示,补齐后原位置替换。
  - 从管道来的内容无法跟随,按 `F` 会提示 `follow needs a file`。
- **过滤**(`&`):输入一段子串,只保留命中的行;视口、行号、折行都在过滤后的行集合上重新计算,并按内容锚点尽量保持当前位置。再按 `&` 直接回车即清除过滤。
- **按词折行**(`w`):默认按显示宽度硬切(和 less 一致,中文长句会被切断);打开后优先在最后一个空白处断行,超长单词才会硬切,并保证不产生空行。
- **底栏宽度不够时**:先切名字,进度与开关指示始终保留。

## 光标

界面**不使用物理光标**:动画每帧都在重绘,diff 的落点每帧都不同,把物理光标摆到提示符位置会跟着乱跳。改为在缓冲里画一个实心块当光标,物理光标全程由 ratatui 隐藏,只在退出时恢复。

实测(pty 抓取整段会话字节流):整段会话只出现 **1 次** show-cursor 转义,且位于退出那一帧。

## 实测字节吞吐

100x40 终端,统计首帧之后 1.6 秒内写入终端的字节(`/tmp/neon_sample.txt`,71 行混排中英文):

| 配置 | 字节/秒 |
| --- | --- |
| `--no-anim`(静止) | 0 |
| 默认(rainbow + flow 2,30fps) | 约 1.15 MB/s |
| 默认 + `-n` | 约 1.16 MB/s |
| `--no-rainbow`(flow 2) | 约 618 KB/s |
| `--flow 1`(rainbow) | 约 604 KB/s |
| 默认 + `--fps 10` | 约 634 KB/s |
| 默认 + `--fps 15` | 约 937 KB/s |
| `--flow 4` | 约 1.76 MB/s |

量化之前(流速 1.0):不开字形上色是 954 KB/s,rainbow 是 2.3 MB/s。当前默认是 rainbow + flow 2,约 1.15 MB/s —— 流速比当年翻倍,字节量还不到当年 rainbow 的一半。

流速与字节量成正比,因为色相转得越快,每帧跨过量化台阶的格子越多。实测同一格 1.2 秒内出现的颜色数:`--flow 1` 8 种、默认(2.0)15 种、`--flow 4` 31 种。

终端跟不上的时候按顺序试:按 `a` 冻结(0 字节/秒)、按 `r` 关掉字形上色(约 618 KB/s)、`--fps 10`(约 634 KB/s)、`--no-rainbow --flow 1`。

## 实现要点

- `doc.rs`:载入与追加文本,展开 tab 到 8 的制表位,把控制字符写成 `^X`,再按**显示宽度**折行(全角字符占 2 格,不会被劈成两半;剩余不足 2 格时整字推到下一行)。文本以"完整行 + 一段还没等到换行的尾巴"保存,所以追加时半行能原地补全,不会出现撕裂或重复。搜索与过滤都在这套"显示行"上做,坐标用字节偏移,切片永远落在字符边界。
- `pager.rs`:视口、滚动、搜索定位、行号表(过滤)、高亮的列区间映射。纯逻辑,可单测;重排(改列宽、切折行、切行号、改过滤)时按内容锚点保持视口位置,不会跳回文件开头。
- `ui.rs`:正文占第 0 行到底栏上一行,底栏是最后一行(所以 `view_h = 终端高度 - 1`);先用 `Paragraph` 写出字符,再逐单元格改颜色。空白格子不参与流动(否则每帧要重写大量空格,白白多出几十 KB),只做去残留处理。宽字符的第二格只补底色。
- `rainbow`(默认开):正文每个字形按 `(x + 2y)` 的视口位置取色相,所以整屏是一道斜着的连续光谱;`--no-rainbow` 时只有光带染色,其余字形是基色。
- `neon.rs`:HSL 色相环 + 环形高斯光带 + 量化台阶。正文颜色只依赖**视口坐标**,所以滚动时屏幕上的颜色图案不动,只有内容从下面滑过去 —— 这同时让滚动的 diff 只涉及新露出的那一行。
- `main.rs`:命令行解析、终端进出、事件循环,以及跟随用的文件尾读器(按位移增量读,跨 chunk 的 UTF-8 边界单独处理)。
- 输入:给了文件就读文件;没给文件且 stdin 不是 tty 就读 stdin;键盘事件由 crossterm 走 `/dev/tty`,因此 `cat f | neon` 可用。
- 框线只用 ASCII(`+ - |`),霓虹感全部由颜色承担,不引入装饰性 Unicode 字符。
