# graph-tui

终端里的**通用图渲染引擎**:输入一张图(节点 + 边 + 边分组),输出字符格画面。
边是正交折线,拐角是圆角制表符 `╭╮╯╰`,两条边交叉时一条从另一条下面穿过(断一格),
一格只留一种颜色,每个分组一种颜色。

```
                   North Gate ◎────────────╮
                              │            │
                              │            │
                              │────────────○────────────╮
                              │         Museum          │
                              │                         │  Harbour    分组
                              │                         │     ○       ── 1
                              │                         │     │       ── 2
 West End                     │                         │     │       ── 3
     ○────────────────────────◉─────────────────────────◎─────╯
                              │                     East Dock         ○ 节点
                              │                                       ◎ 枢纽
                              │                                       > 有向边
                              │
                              ○ South Park
节点 7  边 8  分组 3  真实坐标  光标 Central  1  2  3
```

(上面是 `examples/metro.dot` 的 `--dump` 输出,略去上下空行;`--dump` 打一帧真彩 ANSI 就走。)

## 构建

```bash
cargo build --release
cargo install --path .          # 装到 ~/.cargo/bin
```

依赖只有 `ratatui` / `crossterm` / `unicode-width`,运行时没有网络也没有数据库。

## 用法

```bash
graph-tui examples/pipeline.dot          # 打开文件(默认按图自己挑布局)
graph-tui < deps.dot                     # 没有文件名就从 stdin 读
graph-tui --dump --size 120x36 x.dot     # 打一帧就退出,方便截图/塞进文档
```

```
--file <path>      读 .dot(`-` 表示 stdin;也可以直接把路径当参数给)
--layout <name>    geo | relax | force | layered,默认按图自己挑
--dump             打一帧真彩 ANSI 到 stdout 后退出
--size <WxH>       --dump 的画布尺寸(默认 200x50)
--labels           开局就把节点名都标出来(等于按 b)
--at <name>        开局把光标停在这个节点上
--find <text>      开局先搜一遍(名字 / 别名 / 分组号)
--lang <zh|en>     界面语言(默认 zh;命令行帮助与报错固定英文)
-v, --version      版本
-h, --help         帮助
```

## 布局

| 名字 | 做什么 | 要求 |
| --- | --- | --- |
| `geo` | 直接用输入自带的坐标(等距圆柱那种真实坐标也认) | 每个节点都要有 `pos` |
| `relax` | 从输入坐标出发做弹簧放松,站距拉匀、走向吸附到 `- \| / \` 四种笔画 | 每个节点都要有 `pos` |
| `force` | 力导布局(Fruchterman-Reingold),结束时同样吸附成横竖 45 度 | 任意图 |
| `layered` | 分层布局(Sugiyama 那一套),适合有向依赖图/流程图 | 任意图(有环也能画) |

不指定 `--layout` 时:有坐标就用 `geo`,没坐标就在 `force` 与 `layered` 之间按图有没有环来挑。
`r` 键在原地循环这四套。**同一张图换布局不会动光标**,搜索与聚焦都按节点保留。

四套布局都是**确定性**的:同一张图跑两次结果逐点相同(没有随机数)。

## 键位

| 键 | 做什么 |
| --- | --- |
| `h j k l` / 方向键 | 往那个方向挑屏幕上最近、最正的那个节点(`5l` = 连挪 5 个) |
| `H K` / `J L` | 沿分组走一个(这个分组自己的顺序,和屏幕方向无关);同一节点上有多条分组可走时弹列表选 |
| `+` `-` `0` | 放大 / 缩小 / 复位 |
| `空格` `z` | 把当前节点挪到画面正中 |
| `f` | 把聚焦的分组(没聚焦就是当前节点所在的分组)铺满画面 |
| `b` | 开关节点名标注 |
| `/` | 搜节点名、别名、首字母缩写;纯数字 = 聚焦那个分组 |
| `n` `N` | 下一个 / 上一个搜索命中 |
| `V` | 聚焦当前节点所在的分组(再按一次取消) |
| `r` | 循环切换四套布局 |
| `Ctrl-d` `Ctrl-u` | 半屏往下 / 往上跳 |
| `Ctrl-o` `Ctrl-i` | 回到上一个 / 下一个跳过的节点(`Tab` = `Ctrl-i`) |
| `?` | 键位速查(任意键关掉) |
| `:` | 命令行:`layout <名>` / `side <倍数>` / `cycle <倍数>` / `lang <zh\|en>` |
| 鼠标 | 左键点节点跳过去、按住拖动平移、滚轮缩放、`Ctrl`+滚轮平移 |
| `q` / `esc` | 退出 |

光标所在的那个节点是实心的(`●` / `◉`),按心跳节奏在亮白与红色之间闪。

## 输入格式

认 `.dot` 的一个子集(graphviz 的隐式建节点语义:边提到没声明过的名字就自动建一个):

```
digraph deps {
  node [shape=box];                                  // 默认属性,可省
  "core" [pos="0,0", label="核心层", terms="hexin|hx"];
  "view" [pos="4,0"];
  "core" -> "view" [color="#4c8ef8", group="ui"];    // 有向边,在 view 那头画箭头
  "view" -- "core" [group="ui"];                     // 无向边
}
```

- 节点:`pos="x,y"`(x 向右、y 向上,单位随意,只有相对关系有意义)可选;
  `label` 换显示名;`terms="a|b|c"` 与 `pinyin` / `pinyin2` 都进搜索别名。
- 边:`--` 永远无向,`->` 永远有向,`<-` 是反过来的有向边;
  `group=` 与 `line=` 都算分组名(决定颜色,也决定沿线走的顺序),
  `color="#rrggbb"` 不写就按调色板发。
- `digraph` 里没写箭头的边算有向;`subgraph` 当透明容器,里面的节点与边照收。

`examples/` 里有三张现成的图:`metro.dot`(带坐标的线路图)、
`pipeline.dot`(无坐标的有向无环图)、`deps.dot`(模块依赖,含一个二元环)。

## 与 metro-tui 的关系

渲染器(方向位合成字形、交叉下穿、一格一色、标签摆放)与 `relax` 的弹性松弛流程,
都搬自同一个作者的 [metro-tui](https://github.com/mixsoulgithub/metro-tui),
在这里把地铁语义(`线路` / `车站` / `换乘`)泛化成了 `分组` / `节点` / `枢纽`:
metro-tui 是这个引擎的一个特例。许可都是 MIT。

## 压力用例(examples/limits/)

这一批是故意为难引擎的图,拿来量边界在哪:

| 文件 | 试什么 |
| --- | --- |
| `star40.dot` | 一个枢纽挂 40 片叶子:一格只有四个方向,扇出到极限 |
| `k12.dot` | K12 完全图:66 条边挤在 12 个点上 |
| `grid20.dot` | 20x20 网格 400 点 760 边:密度与耗时 |
| `chain60.dot` | 60 长链、走分层:层高 3 格 x 60 层,窗口不够高就叠起来 |
| `ring.dot` | 有向环,分层布局必须拆一条回边 |
| `parallel.dot` | 同一对节点四条边四个分组:必然重叠 |
| `selfloop.dot` | 自环:引擎直接拒绝(报错) |
| `isolated.dot` | 孤立节点 + 一个连通块 |
| `components.dot` | 四个互不相连的连通块 |
| `inarrow.dot` | 12 条入边指向同一个点:箭头只有四个方向可放 |
| `collinear.dot` | 八个节点共线 |
| `samepos.dot` | 五个节点坐标完全重合 |
| `outlier.dot` | 一个远端离群点撑开包围盒 |
| `dupname.dot` | 两个同名节点(.dot 语义上就是一个节点) |
| `longlabel.dot` / `cjk.dot` | 超长标签与中文标签的占位 |

状态栏里那一条 `挤 N` 就是给这些图用的:投影之后有 N 个节点跟别人落在同一格
(窗口不够大,或者输入坐标本身就重合),画面看不出来,所以直接报出来。

## 真实世界的图(examples/real/)

这几张不是编的:每一张都是手边的真实数据直接转出来的,文件头写着来源与重算办法。

| 文件 | 数据来源 | 规模 |
| --- | --- | --- |
| `modules.dot` | 本 crate 自己的模块依赖(源码里的 `crate::xxx` 引用) | 11 模块 18 边 |
| `cargo-deps.dot` | 本 crate 的 `Cargo.lock`,只展开一层 | 21 包 18 边 |
| `schema.dot` | 本机 Elisa 音乐播放器数据库的外键(`pragma foreign_key_list`) | 12 表 8 外键 |
| `systemd.dot` | 本机 `dbus.socket` 的反向依赖(`systemctl show` 的 Requires / Wants / After) | 21 单元 51 边 |
| `tcp.dot` | TCP 连接状态机(RFC 793) | 11 状态 17 边 |

这五张都是 11~21 个节点 —— 不是巧合:终端画得下、人也读得下的图,差不多就是这个量级。
再往上(比如把 `Cargo.lock` 的传递依赖全展开,一百多个包)画出来只是一团麻,
GUI 也一样,那不是终端的问题。

`tcp.dot` 里没有自环:RFC 那张图几乎每个状态都有指向自己的边(重传、超时、重发 FIN),
而本引擎当前不收自环(`"a" -- "a";` 会直接报错),所以只画了状态之间的转移。

## 已知取舍

- 走线只有正交:45 度的边在屏幕上折成一条 L,没有 `╱ ╲ ╳` 这类斜笔画(东亚宽度不确定)。
- `○ ◎ ─` 这类字形在部分 CJK 字体下会被画成两格宽,图会错位。
- 节点没有形状与尺寸概念,标签也不画引线;位置冲突时标签会被挤掉。
- `layered` 是 Sugiyama-lite:分层、重心排序、回边拆解都有,但没有交叉最小化的正交布线器,
  层多的图会画得很"竖"。
- `geo` 要求每个节点都有坐标;拿不到坐标就用 `force` 或 `layered`。
- 规模:6000 节点无坐标的 `force` 约 3.5 秒(release),再往上靠迭代轮数封顶兜着。
